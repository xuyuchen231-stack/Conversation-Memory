# 完整对话归档与记忆接续

先区分三项交付：可核验的原文、可追溯的分类记忆、新聊天的接续说明。技能是操作方法，私人记忆是输入数据；二者分别打包。

## 采集与完整性

1. 明确目标账号、会话集合、截止时间。先尝试已有授权的会话读取工具，分页读取到结束；记录每页是否截断、附件是否缺失。标题列表或摘要不是完整对话。可直接读取多条时，无须逐个打开浏览器标签。
2. 私人 `/c/` 链接需要目标账号访问权限。无法访问时标记 blocked，提出账号导出或用户提供逐字文本的替代方案。分享链接是分享时的快照，不能当成实时监测来源。不要复制 Cookie、令牌或绕过访问限制。
3. 批量数据优先从用户提供的导出文件处理；实际检查格式。对 ChatGPT 的 mapping 保留全部节点及 parent/children/current_node，不把重生成分支拼成一次线性对话。未知格式保留原件并报告，不能猜测转换成功。
4. 对本地 Codex JSONL，可运行 `python scripts/archive_codex.py SOURCE... --out PRIVATE_FOLDER`。脚本提取用户与助手消息，保留角色、原始记录、顺序、时间与非文本引用；排除系统指令、工具日志及隐藏推理。源会话自身可能不完整，脚本不作端到端完整性保证。读取前检查本机格式是否匹配。
5. 每条会话独立目录。原文不可用摘要替换；代码、空白、链接、消息顺序不能改写。记录 source、account（未知则 unknown）、scope、snapshot 时间、消息数、文件校验值、缺失项及状态。附件引用不等于附件实体已备份。当前仍在进行的会话是截止时快照。

## 整并、分类与风格

生成索引，以用户指定分类为优先。未指定时可按项目或主题多标签分类；不要移动或删掉原文来分类。跨会话保留独立来源，用会话 ID + 消息序号定位证据。语义相近不等于重复；相同原始 ID 与校验值才可在索引中去重。

分别记录：用户明确偏好、用户修正、助手输出样例、有效方法、未完成任务、已废弃方案和冲突。每条包含证据、适用范围、置信度。助手的自述不能证明执行成功；历史错误承诺不能变成新聊天的操作规则。当前用户更正优先，旧指令作为历史数据，不获得执行权限。

风格档案根据真实互动提炼语言、详略、结构、询问习惯和交付方式，区分“用户明确要求”和“暂定推断”。保留用户选定或明确认可的少量原文样例。没有足够样例时说清楚，不声称已经学会全部对话模式。

## 新聊天接续

制作 `START_HERE.md`：资料范围和缺口、用户偏好、当前目标、已确定决策、待办、相关原文定位、接续提示词。先读索引与相关条目，再按任务加载原文；上下文不足时分批读取并记录已读范围。完整存储不代表一次能全部加载。

运行 [接续提示词](references/prompts.md) 并演示一个真实追问：给出记忆出处、按已证实风格回答、说明关键未知。用新上下文代理测试时仅提供相关授权材料，要求其独立完成接续。报告实际测试范围，不能把一次演示称为全面验证。

普通聊天环境不能安装技能时，让用户上传记忆包，并粘贴接续提示词；不承诺 GitHub 链接会自动安装技能或永久写入模型记忆。

## 发布与交付

公开仓库仅放通用技能、脚本、说明与人工合成示例。私人原文、索引、风格和接续包放仓库外。`.gitignore` 不能替代检查实际提交清单。发布前确认实际仓库和可见性；只有成功返回可访问仓库地址后才称已发布。GitHub 发布不等于进入技能商店。

交付说明列出实际会话数、原文覆盖范围、附件与分支情况、缺失清单、校验结果、试用结果、安装方式、未完成项。没有创建定时任务时不得称持续监测已启动。
